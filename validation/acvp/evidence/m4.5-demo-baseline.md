# M4.5 ACVTS Demo Baseline

This document records the NGI541 implementation baseline selected for
external evaluation against the NIST ACVTS Demo environment.

The purpose of this baseline is to make the implementation, ACVP capability
registration, dependency revision, and validation environment used for the
M4.5 external-validation phase reproducible and auditable.

## Validation scope completed before M4.5

The implementation entering M4.5 has completed the local ACVP validation
phase for the currently declared algorithms.

The completed validation scope includes:

- public NGI541 execution API coverage;
- AES-CBC ACVP AFT support;
- AES-CBC Monte Carlo Test support;
- AES-CTR ACVP AFT support;
- AES-CTR Counter Test support;
- AES-GCM AFT support;
- AES-GCM encrypt/decrypt coverage including zero-length payload and AAD cases;
- SHA2-224 AFT support;
- SHA2-224 Monte Carlo Test support;
- SHA2-256 AFT support;
- SHA2-256 Monte Carlo Test support;
- semantic registration verification;
- offline ACVP JSON end-to-end execution;
- direct ACVP callback KATs;
- public API negative-conformance testing;
- ACVP callback negative-conformance testing;
- engine initialization-state validation;
- GCC and Clang CI validation;
- production/validation architecture-boundary checks.

The ACVP validation layer invokes the public NGI541 execution API rather than
the internal engine ABI.

## M4.5 objective

M4.5 transitions NGI541 from locally generated ACVP validation evidence to
external ACVTS-generated validation evidence.

The target execution path is:

NIST ACVTS Demo
→ pinned libacvp
→ NGI541 ACVP registration and callbacks
→ public NGI541 API
→ NGI541 production engine

The primary M4.5 success criterion is that NIST-generated vector sets for all
declared algorithms are successfully processed by NGI541, submitted to the
ACVTS Demo service, and receive passing server verdicts.

## Evidence to record during M4.5

For each relevant ACVTS Demo session, record:

- NGI541 commit;
- libacvp revision;
- ACVP registration SHA-256;
- execution environment;
- compiler and version;
- ACVTS test session ID;
- vector set IDs;
- algorithms exercised;
- non-secret response artifacts where appropriate;
- ACVTS server verdicts;
- date of the session.

Credentials and authentication secrets must never be stored in this
directory.

In particular, do not commit:

- ACVTS client private keys;
- TOTP secrets;
- access tokens;
- JWTs;
- passwords;
- other authentication material.
